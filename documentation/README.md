# Selective Inference for DV-Score Data Valuation

Technical documentation of the **active** code path:

- `data_valuation` ∈ `{ "lava", "cg-score" }`
- `method = "parametric_nested"`

Everything else in the repository (`method="parametric"`, `"overconditioning"`,
the `NaiveTest`/`FSNaiveTest`/`DataSplittingTest` diagnostics, the dead
`LPsolver.py`/`param.py` scaffolding, the older `data/`, `model/`, `utils/`,
`evaluate/`, `cg_score/` trees) is out of scope here and is only mentioned where
it is required to understand the active path.

---

## 1. What the package computes

Given a training set `(Xtrain, ytrain)`, an optional validation set
`(Xval, yval)`, and a fraction `fraction`:

1. A **data-valuation selection algorithm** picks a subset of training samples
   (the "selected instances") — either the LAVA OT score or the CG-score.
2. A **Lasso** is fit on the selected samples; its support defines an active
   feature set `M`.
3. One feature position `j` inside `M` is tested (the "tested index").
4. The package returns a **selective p-value** for `H0: beta_{M[j]} = 0`, valid
   *conditional on the selection event* (both the DV selection and the Lasso
   support). The conditional distribution is a **truncated normal on the
   selection region**, approximated by scanning a one-dimensional statistic
   along the line `y(z) = a + b z` (the "parametric" direction).

The `parametric_nested` method computes the selection region exactly (not on a
fixed grid): it enumerates the nested conditioning events

```
OT basis interval  ->  sort-condition regions  ->  Lasso-support regions
```

and keeps the union of pieces where the local Lasso support equals the observed
support `M`.

## 3. Public API and call chain

`si_for_cg/__init__.py` re-exports the public surface. The active chain is:

```
SI_DV(...)                         si_for_cg/si_dv.py:444
  -> SelectiveInference(...).fit   si_for_cg/si_dv.py:300
       -> adapter.select(...)                     # DV selection
       -> solve_Lasso(...)                        # initial active set M
       -> make_eta_cgFS(...)                       # test statistic eta
       -> selective_inference(...) si_runner.py:15  # dispatch by method
            -> parametric_intervals_FS_nested      # lava
            -> cg_parametric_intervals_FS_nested   # cg-score
            -> compute_p_value(...)                # truncated-normal p-value
```

`SelectiveInference` constructor (`si_for_cg/si_dv.py:303`) validates
`data_valuation ∈ {"lava","cg-score"}` and builds a frozen `SIConfig`
(`si_for_cg/si_types.py:19`) holding `zmin, zmax, step, atol, data_valuation`,
plus a mutable `LassoInfo` (`si_for_cg/si_types.py:27`) holding `lambda_`, `M`,
`Mc`, `sM`.

### 3.1 `SelectiveInference.fit` step by step (`si_dv.py:320`)

1. Coerce `Xtrain`/`ytrain` to arrays, validate shapes.
2. Optional `Sigmat`/`Sigmav` are block-diagonalised (`si_dv.py:341`).
3. **Selection** (`si_dv.py:347`):
   - `lava` → `SelectionAdapter(fraction).select(Xtrain, ytrain, Xval, yval)`
   - `cg-score` → `CGSelectionAdapter(fraction).select(Xtrain, ytrain)`
   The returned `observed_selection` is a sorted list of sample indices.
4. **Initial Lasso** (`si_dv.py:367`):
   `M, Mc, sM = solve_Lasso(Xtrain[observed_selection], ytrain[observed_selection], lambda_)`.
   `M` is the active feature set, `Mc` its complement, `sM` the signs of
   `beta` on `M`.
5. Guards: empty DV selection or empty `M` raise `ValueError` (`si_dv.py:373-376`).
6. **Tested position** (`si_dv.py:380`): random index in `range(|M|)` unless
   `jth` is given. **`jth` is a position inside `M`, not a global feature
   index.**
7. **Test statistic** `eta` via `make_eta_cgFS` and dispatched to
   `selective_inference`:
   - `lava` (`si_dv.py:382`): stacks `X = vstack([Xtrain, Xval])`,
     `y = concat([ytrain, yval])`, builds `eta` on the stacked data, passes
     `Sigma_arr` (block-diag of `Sigmat`/`Sigmav` or `I_{nt+nv}`).
   - `cg-score` (`si_dv.py:408`): `eta` on `Xtrain` only, `Sigma_arr = Sigmatt`
     or `I_nt`.
8. Stores `p_value_`, `intervals_`, `selected_indices_`, `tested_index_`.

`SI_DV` (`si_dv.py:444`) is a thin wrapper returning `si.p_value_`.

### 3.2 Test statistic construction (`si_adapter.py`)

`make_eta_cgFS(X, M, j)` (`si_adapter.py:160`) builds, for feature set `M`,

```
eta = (e_j^T (X_M^T X_M)^{-1} X_M^T)^T
```

i.e. the row of the least-squares "hat" operator that maps `y` to
`beta_hat_{M[j]}`. The dimension of `eta` is `n` (`cg-score`) or `nt+nv`
(`lava`, columns for validation rows are zero). Crucially, `eta` depends **only
on the feature set `M`**, not on which samples were selected — this is why the
conditioning event is `{z : M(z) = M_obs}` and not the sample top-k (see §6).

`make_etaFS` (`si_adapter.py:139`) is the same construction used by the naive
test; `make_eta`/`make_eta_cg` are the sample-based variants used by
`NaiveTest`.

## 4. Selection pipelines

Both adapters expose `select`; the runner is agnostic to which is used.

### 4.1 LAVA — `SelectionAdapter` (`si_adapter.py:38`)

`select(Xtrain, ytrain, Xval, yval, basis_hint=None)` calls
`calc_lava_score` (`lava_function.py:65`):

- Stacks `[X | y]` for train and val, forms the OT equality constraints
  `S_ = OptimalTransport.convert(nt, nv)[:-1]`, `h_` (dropping the last,
  redundant row).
- Solves the OT LP with `OptimalTransport.solveOT` (`OptimalTransport.py:83`),
  which calls the **patched scipy** `linprog(method="simplex")` and reads
  `res.basis`.
- Recovers dual potentials `lambda_vec = solve(S_basis^T, cost[Basis])` and
  returns the calibrated training scores
  `values = (nt/(nt-1)) f_train - sum(f_train)/(nt-1)`.
- With `return_complement=True` it also returns `S_`, `h_`, `Basis`, `cost`,
  which the adapter stores as `self.S_`, `self.h_`, `self.basis`, `self.cost`
  (`si_adapter.py:61-64`). These are needed later for the parametric trace.

`fraction <= 1` is a proportion of `nt`; `fraction > 1` an absolute keep count
(`si_adapter.py:72`). Top-k are the largest scores; indices are returned sorted.

`select_with_known_basis(nt, S_, cost_vec, Basis)` (`si_adapter.py:81`) is the
z-local selection used inside the scan: given a *fixed* OT basis it solves the
dual system `scores = -solve(S_basis^T, cost_vec[Basis])`, applies the same
calibration, and returns the top-k selection **and** the full sort permutation
`argsort(scores)`.

### 4.2 CG-score — `CGSelectionAdapter` (`si_adapter.py:12`)

`select(X, y)` calls `calc_cg_score` (`cg_function.py:44`):

- Builds the ReLU-NTK Gram matrix
  `H_ij = (x_i^T x_j)(pi - arccos(x_i^T x_j)) / (2 pi)` with diagonal `1/2`
  (`gram_matrix.py:5`), inverts it once, and caches `self.invH`.
- Scores are the leave-one-out quantities `scores_k = (v_k)^2 / d_k` with
  `v = invH @ y`, `d = diag(invH)` (`cg_function.py:81-84`).
- Top-k by score; `sorted_indices` is cached (used by the cg walk).

There is no OT LP and no validation data on this path.

### 4.3 Initial Lasso and KKT validation — `solve_Lasso` (`si_utils.py:619`)

Fits `sklearn.Lasso(alpha = lambda_/n, fit_intercept=False)`, then **validates
the primal KKT residual** (`si_utils.py:634`) and retries with tolerances
`1e-12, 1e-14` if the first coordinate-descent pass has small duality gap but
the wrong support. If KKT tolerance is not met it raises `RuntimeError`; the
experiment scripts catch-and-skip. Returns `M, Mc, sM`.

## 5. Decomposition along the parametric line

`decompose_y(y, eta, Sigma)` (`si_utils.py:594`) builds the standard
selective-inference decomposition `SIDecomposition` (`si_types.py:35`):

```
etaT_Sigma_eta = eta^T Sigma eta
b              = Sigma eta / etaT_Sigma_eta
a              = (I - b eta^T) y
etaT_y         = eta^T y
```

so that any point on the line `y(z) = a + b z` leaves `eta^T y(z) = z`. The
parametric scan moves along `z` and asks which selection would have produced the
current `z`.

---

## 6. The conditioning event (why `parametric_nested`)

The tested statistic uses only `X[:, M]` (§3.2), so the exact selection event is

```
{ z : M(z) = M_obs }   (Lasso support equals observed support)
```

The sample top-k (DV selection) is **not** part of the event: within a sort
region the top-k is constant and merely fixes *which rows* the Lasso is fit on.
The `parametric_nested` scan therefore enumerates, in nested order:

1. **OT basis intervals** (lava only) — the LP basis is piecewise constant in
   `z`; the observed basis is kept and never re-solved (§9).
2. **Sort-condition regions** — z-intervals on which the DV-score permutation is
   fixed.
3. **Lasso-support regions** — z-intervals on which the Lasso support is fixed.

It keeps pieces where the local support equals `M_obs` and finally checks that
`z_obs = etaT_y` lies in the union (else `RuntimeError`).

The stock `parametric_intervals_FS` (`si_parametric.py:25`) instead jumps to the
last joint-intersection piece per region and can **miss** event pieces; the
nested walk does not. This is the whole reason `parametric_nested` exists.

## 7. Runner and dispatch — `si_runner.selective_inference` (`si_runner.py:15`)

Recomputes the decomposition (same `a,b` as `fit`) and dispatches:

- `config.data_valuation == "lava"` (`si_runner.py:32`): `y = concat(ytrain,yval)`;
  `parametric_nested` → `parametric_intervals_FS_nested`.
- `config.data_valuation == "cg-score"` (`si_runner.py:58`): `y = ytrain`;
  `parametric_nested` → `cg_parametric_intervals_FS_nested`.

Then `compute_p_value(intervals, etaT_y, etaT_Sigma_eta, type="two-sided")`.
Returns an `SIResult` (`si_types.py:46`) with `p_value`, `intervals`, `etaT_y`,
`etaT_Sigma_eta`, `observed_selection`, `tested_index`, `method`.

Note the cg-score call site uses **positional** arguments matching the signature
`selective_inference(Xtrain, Xval, ytrain, yval, Sigma, adapter, fs, eta, ...)`
(`si_dv.py:416`).

## 8. `parametric_nested` for LAVA — `parametric_intervals_FS_nested` (`si_parametric.py:140`)

### 8.1 Precompute (`si_parametric.py:176`)

Using `OMEGA = OptimalTransport.constructOMEGA(nt, nv)` and the stacked `X`, the
per-constraint OT cost is an exact quadratic in `z`:

```
wt = c_ + Omega_a*Omega_a      # z^2 coefficient is ot
rt = 2*Omega_a*Omega_b
ot = Omega_b*Omega_b
```

where `c_ = sum_i (OMEGA X_i)^2`, `Omega_a = OMEGA a`, `Omega_b = OMEGA b`, and
`a_vec, b_vec` come from the decomposition. `z_obs = decomposition.etaT_y`.

### 8.2 Trace the OT basis path (`si_parametric.py:209`)

`trace_parametric_bases` (`si_parametric.py:723`) is run for the right (`+1`,
towards `zmax`) and left (`-1`, towards `zmin`) directions from `z_obs` with the
**observed basis**. Each step:

- `_basis_optimal_region` (`si_parametric.py:577`) computes the reduced-cost
  quadratics `RC_i(z) = rc_w z^2 + rc_v z + rc_u` for non-basic variables (via
  `pi = solve(B.T, c[basis])`, no explicit inverse; see
  [`runtime_blas_threads.md`](runtime_blas_threads.md)), intersects
  `RC_i(z) >= 0` with `solveinterval(-rc_w,-rc_v,-rc_u, z)` (`si_utils.py:271`),
  and returns the containing optimal region plus the entering-variable candidates
  at the boundary in the requested direction.
- `_pivot_basis` (`si_parametric.py:668`) performs a deterministic simplex pivot
  (min-ratio test with Bland tie-break on the leaving variable, entering chosen
  as `min(candidates)`).
- The loop advances `z` just inside the next basis region.

The left/right paths are joined at the observed basis: if the meeting bases
match, the combined `list_da_itv` is `reversed(left_path[1:]) + [joined] +
right_path[1:]` (`si_parametric.py:215-221`). **The OT path is never re-solved
at other `z`**; the observed basis is authoritative (see `DEBUG.md` for the
known OC-vs-z bug this avoids).

**Note:** The two directions run concurrently on a 2-worker
`ThreadPoolExecutor` (`si_parametric.py:211-217`) from the observed basis; `H`
is shared read-only, so nothing is pickled. Per `AGENTS.md`, do **not** switch
to a process pool here — `H` would be pickled per task while BLAS
oversubscribes. This 2-thread split is also why the per-process BLAS thread
count matters so much (see [`runtime_blas_threads.md`](runtime_blas_threads.md)).

### 8.3 Sort-region walk — `iter_sort_regions` (`si_sort_walk.py:272`)

For each OT interval `(ml, mr, B)`:

- `score_coefficients` (`si_sort_walk.py:59`) solves the same system as
  `sort_conditioning` once (`lu_factor` + `lu_solve` on `S_[:,B].T`) to get each
  train sample's score as an exact quadratic `s_i(z) = c2 z^2 + c1 z + c0`. The
  DV calibration cancels in pairwise differences.
- `iter_sort_regions_table` (`si_sort_walk.py:207`) walks regions left→right at
  grid step `config.step`. At each point it intersects the pairwise
  score-difference inequalities (`region_containing`, `quad_pieces`) to get the
  containing sort region `[sl, sr]`, yields `(z_entry, sl, sr, selection)` where
  `selection` is the top-k implied by the permutation, then **infers the next
  permutation** at the boundary via `flip_reversal` (`si_sort_walk.py:160`):
  tight adjacent pairs form maximal tie groups; a group is reversed iff it has a
  strict slope drop. The inference is verified by a continuity check; degenerate
  cases fall back to the real sort (`_resort`, `si_sort_walk.py:193`).
- `MAX_STALE = 1000` consecutive gaps before giving up; `TOL=1e-9`,
  `TOL_CONT=1e-7`.

Inference is valid **only inside one OT interval** (at an OT boundary the basis
pivots and the quadratics change), so each OT interval is re-seeded with one
real sort computation.

### 8.4 Lasso-support sub-walk (`si_parametric.py:233`)

Inside each sort region (rows fixed by `selection`):

```python
M, Mc, sM = solve_Lasso(Xtrain[selection], (a_vec + b_vec*zl)[selection], fs.lambda_)
fs_itv    = conditioning_Lasso(Xtrain[selection], a_vec[selection], b_vec[selection],
                               fs.lambda_, M, Mc, sM)
fpiece = containing_piece(interval_intersection(fs_itv, [(sl, sr)]), zl)
if np.array_equal(fs.M, M):
    final_interval.append(fpiece)
zl = fpiece[1] + config.step
```

`conditioning_Lasso` (`si_overconditioning.py:203`) derives the polyhedral
region in `z` where the current Lasso support/signs stay optimal, via
`solve_linear_inequality` (`si_utils.py:208`). Failures (`RuntimeError`,
`ValueError`) advance `zl` by `step`, up to `MAX_STALE`. The union of accepted
pieces is `interval_union`-merged and must contain `z_obs`.

**Event-driven variant (default since `SIConfig.lasso_path = True`).** The
restart-and-solve loop above re-fits the Lasso at every support boundary. With
`lasso_path` enabled it is replaced by `walk_lasso_support_regions`
(`si_lasso_path.py`), which solves the Lasso once per merged selection span and
*infers* each following support region from the KKT inequality that becomes
tight at the current region's boundary (homotopy / LARS-style), falling back to
a real solve on degenerate events. See
[`lasso_condition_tracking.md`](lasso_condition_tracking.md) for the algorithm,
conventions and accuracy tests. Set `config.lasso_path = False` to restore the
literal loop above.

## 9. `parametric_nested` for CG-score — `cg_parametric_intervals_FS_nested` (`si_parametric.py:323`)

Simpler than lava because the cg-score quadratics

```
CG_i(z) = (u_i + v_i z)^2 / d_i,   u = invH a,  v = invH b,  d = diag(invH)
```

are **globally valid** on the whole real line (`invH` depends only on `X`, and
no OT basis is ever re-solved). So there is no OT layer:

1. `n_keep` follows the adapter rule (`fraction <= 1` proportion, else count).
2. `iter_cg_sort_regions` (`si_sort_walk.py:321`) builds the global table via
   `cg_score_coefficients` (`si_sort_walk.py:292`) and walks `[zmin, zmax]` with
   `iter_sort_regions_table` (same inferred-walk engine; fallback `_resort_cg`
   just re-evaluates the exact table).
3. For each sort region, the same Lasso-support sub-walk as lava
   (`si_parametric.py:375`), keeping pieces where `M == fs.M`.

The union must contain `z_obs` or it raises.

## 10. Interval algebra and p-value

### Intervals (`si_utils.py`)

- `interval_union` (`si_utils.py:172`): merge sorted/unsorted intervals.
- `interval_intersection` (`si_utils.py:186`): sweep intersection of two lists.
- `solve_linear_inequality` (`si_utils.py:208`): `b_i x + c_i <= 0` → one
  interval or `[]`; `b==0, c>0` is infeasible.
- `solve_quadratic_inequality` / `solveinterval` (`si_utils.py:229`, `:271`): the
  vectorized batch intersection of quadratics. `solveinterval` is the workhorse:
  every row resolves to EMPTY / ALL / lower / upper / single interval / hole, so
  the batch reduces to `[max lower, min upper] \ union(holes)` — order-independent
  and computed with array reductions. A tolerance snap
  `tol = 1e-9 + 1e-9*scale` mirrors the scalar convention exactly.
- `conditioning_Lasso` (`si_overconditioning.py:203`) → `solve_linear_inequality`.

### `compute_p_value` (`si_utils.py:522`)

Given the merged selection region and `z_obs`, it computes the two-sided
truncated-normal p-value

```
p = 2 * min(mass below z_obs, mass above z_obs) / total_mass
```

on the interval union. Key numerical design (`si_utils.py:530`):

- `mpmath` is used with `mp.dps = 30` (`si_utils.py:21`); every piece mass is
  evaluated in **tail form** (`ncdf(-z_l) - ncdf(-z_r)` when the piece touches
  the right, else `ncdf(z_r) - ncdf(z_l)`) so no `1 - tiny` subtraction is ever
  formed, and the below/above masses are accumulated directly rather than as a
  difference of near-equal CDFs.
- Raises `ValueError` if `etaT_Sigma_eta <= 0` or if the region does not contain
  `etaT_y`; returns `nan` for empty intervals or zero total mass.

`type="two-sided"` is what `selective_inference` passes.

## 12. Numba acceleration (optional)

`si_for_cg/si_numba.py` ports the hot sort walk and small LAPACK/batch helpers to
numba. It is **off by default**; enable with `SI_USE_NUMBA=1`
(`si_numba.py:45`). When `USE and AVAILABLE`:

- `si_sort_walk.iter_sort_regions` dispatches to `w_iter_sort_regions`
  (`si_sort_walk.py:280`); `iter_cg_sort_regions` to `w_iter_cg_sort_regions`
  (`si_sort_walk.py:330`).
- `si_overconditioning.conditioning_Lasso` dispatches to
  `n_conditioning_lasso` (`si_overconditioning.py:204`).
- `OptimalTransport.constructOMEGA` dispatches to `n_construct_omega`
  (`OptimalTransport.py:29`).

Design: `@njit(cache=True, fastmath=False)`; scipy `lu_factor/lu_solve` replaced
by `np.linalg.solve`; tolerances and operation order mirror the pure-Python
reference. Verification harness: `experiment/test_numba_parity.py`
(accuracy + ref-vs-numba integration parity for both `lava` and `cg-score`);
scaling benchmark `experiment/bench_scaling.py`. Per `AGENTS.md`, do **not** use
`ProcessPoolExecutor` for the trace — use `nogil=True`, not `parallel=True`, for
memory-bandwidth-bound kernels.

## 13. Invariants and traps

1. **`jth` is a position inside `M`**, not a global feature index. The statistic
   is built from `X[:, M]` (`si_dv.py:380`, `si_adapter.py:160`).
2. **The observed OT basis must be kept.** Never re-solve OT at a probe `z`;
   that is the `DEBUG.md` bug and the reason the trace starts from
   `adapter.basis`.
3. **Conditioning is on the Lasso support only** (`{z : M(z) = M_obs}`); the
   sample top-k is not part of the event.
4. **Condition intervals (sort / Lasso) are counted separately** by nested
   search, not by the final intersection per visit.
5. **`solve_Lasso` must pass KKT**; experiments catch-and-skip the exceptions it
   raises at Lasso knots.
6. **lava needs the patched scipy** returning `res.basis`; stock scipy raises
   `AttributeError` inside `solveOT`. `si_for_cg/LPsolver.py` is dead.
7. **`fraction` semantics:** `<= 1` proportion, `> 1` absolute count (both
   adapters).
8. **`mp.dps = 30`** is tuned for tail-form p-value CDFs; raise only if a
   consumer needs more digits of the accumulated sums.
9. **The nested scan must contain `z_obs`** in its final region, else it raises
   `RuntimeError` (a genuine inconsistency indicator, not a numerical nuisance).
10. **Run from the repo root** with the `IS` conda env
    (`C:\Users\Asus\anaconda3\envs\IS\python.exe`); scripts prepend the repo root
    to `sys.path`. Running from `experiment/` breaks imports.
